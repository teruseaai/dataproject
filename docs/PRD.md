# PRD: 팀 편성 웹 앱

## 1. 목적

학생들이 팀 프로젝트를 위한 팀을 스스로 편성하는 웹 앱을 만든다. 팀에 들어가지 못한 학생은 AI가 배정을 돕고, 앱이 AI의 답을 규칙으로 검사한다.

## 2. 사용자

| 사용자 | 하는 일 |
|---|---|
| 학생 | 학번과 비밀번호로 로그인한다. 팀 목록과 팀원, 팀원의 주 역할과 보조 역할을 본다. 팀에 지원한다. 내 팀에 들어온 지원에 찬성 또는 거부한다. |
| 관리자(학번 admin) | 명단 CSV와 팀 수로 처음 상태를 만든다. 모집을 마감한다. 남은 학생의 AI 배정안을 받아 확정한다. |

## 3. 팀 규칙

- 확정한 팀 구성에서 모든 팀은 2~4명이다.
- 한 팀에 주 역할이 같은 학생이 2명 이상이면 안 된다.
- 모든 팀에는 기획자를 맡을 수 있는 학생과 웹 프로그래머를 맡을 수 있는 학생이 서로 다른 사람으로 1명씩 있어야 한다. 주 역할이나 보조 역할로 맡을 수 있다.

## 4. 지원과 투표 규칙

- 빈 팀에 지원하면 바로 승인된다.
- 팀원이 있는 팀에 지원하면 대기가 되고, 그 팀의 팀원 모두가 투표한다.
- 모든 팀원이 찬성하면 승인되고, 한 명이라도 거부하면 바로 거절된다.
- 한 번 투표하면 바꿀 수 없다.
- 결과가 나오기 전에는 다른 팀에 지원할 수 없다.
- 지원이 막히는 경우: 팀이 꽉 참, 같은 주 역할의 팀원이 있음, 이미 팀이 있거나 결과를 기다리는 지원이 있음, 모집이 마감됨.
- 결과 안내는 승인, 대기, 거절, 막힘 중 하나로 시작한다.

## 5. 마감과 AI 배정

1. 관리자가 모집을 마감하면 대기 중인 지원은 거절되고, 1명뿐인 팀의 학생은 팀에서 빠진다.
2. 관리자가 AI 배정을 누르면 앱이 AI에게 지금의 팀 구성, 팀이 없는 학생과 역할, 규칙을 보낸다.
3. 앱이 배정안을 검사한다: 빠짐없이 배정, 한 학생은 한 팀에만, 모든 팀 2~4명, 주 역할 중복 없음, 필수 포함 역할 충족.
4. AI가 실패하거나 배정안이 검사를 통과하지 못하면 2차, 3차 모델로 넘어간다. 모델마다 120초 안에 끝나지 않으면 끊는다.
5. 3차까지 실패하면 앱이 모든 경우를 따져 규칙을 지키는 배정을 스스로 찾는다.
6. 규칙을 지키는 배정이 없으면 AI를 부르지 않고 그 이유를 보여 준다.
7. 검사를 통과한 배정안만 관리자에게 보여 주고, 관리자가 확정하면 DB에 저장한다.

## 6. 화면 요구사항

- 자동 채점 프로그램이 화면 요소를 찾을 수 있도록 공고 2.7절 표의 Streamlit key를 그대로 쓴다.
- 로그인한 학생의 팀에 "내 팀"을 표시하고, 팀이 없으면 "아직 팀이 없음"을 보여 준다.
- 이미 팀이 있거나, 결과를 기다리는 지원이 있거나, 모집이 마감되었으면 지원 단추를 비활성화한다.
- 이미 투표한 지원에는 "내 투표"를 보여 주고 단추를 숨긴다.
- 다른 사람의 변경은 새로 고침 단추로 볼 수 있다.

## 7. 데이터

Supabase의 PostgreSQL을 쓰고, 모든 테이블 이름은 `tf_`로 시작한다. 테이블: `tf_students`, `tf_student_sub_roles`, `tf_teams`, `tf_members`, `tf_applications`, `tf_votes`, `tf_settings`. 테이블을 만드는 SQL은 `schema.sql`에 있다. 한 학생은 한 팀에만 속하고 팀의 같은 자리에는 한 명만 들어가도록 DB의 유일성 제약을 둔다.

## 8. 보안 요구사항

- 오픈라우터 키, DB 주소, 관리자 비밀번호는 `.env`에 두고, 배포한 앱에서는 Streamlit Secrets에 둔다. 코드나 깃허브에 올리지 않는다.
- 비밀번호는 bcrypt 해시로 저장한다.
- 학생 계정으로는 관리자 기능을 쓸 수 없다.
- 실제 사람의 이름과 학번은 쓰지 않고 가상 명단만 쓴다.

## 9. 사용한 기술

Python, Streamlit, Supabase(PostgreSQL), psycopg, bcrypt, python-dotenv, requests, 오픈라우터(무료 텍스트 생성 모델 3개), 깃허브, Streamlit Community Cloud.

## 10. 범위와 현재 상태

만든 것: 로그인, 팀 목록, 지원, 투표, 명단 올리기, 모집 마감, AI 배정과 모델 넘어가기, 앱의 자체 배정, 배정안 확정, 새로 고침 단추.

아직 만들지 않은 것(미구현):

- 승인 직전에 규칙을 다시 검사하는 기능
- 필수 포함 역할을 채울 자리가 모자라게 되는 지원을 막는 기능
- 마지막 자리에 두 명이 동시에 들어갈 때 DB 제약으로 처리하는 부분의 화면 안내
- 외부 예약 서비스로 매일 DB에 질의를 보내는 기능
